## What changed vs previous

This is the first `/docs` version for the task-template DSL (v1.0). New in release 1.2.0:

- `tables[]` entries may declare `${varName}` placeholders and a `variables` map of string lists.
- At config load, each templated entry expands via **YAML-text** substitution and **cartesian product** into flat `TableMigrationDefinition` tasks.
- Cap: `maxVariablesCartesianProductsPerTask` (default 16).
- Task names get `varVariant_<N>` when expanded; pre-start Y/N confirm with CLI `-y`/`--yes` for `nohup`.

## TLDR

Avoid copy-pasting nearly identical table migration blocks. Write one template with `${placeholders}`, list alternative string pieces under `variables`, and let the tool expand combinations into parallel tasks (`threadCount`).

## How expansion works

1. Parse config YAML to a tree.
2. For each `tables[]` object **without** `variables`: deserialize as one `TableMigrationDefinition`.
3. For each entry **with** `variables`:
   - Fail if the template body (entry minus `variables`) has no `${…}` placeholders.
   - Fail if a placeholder has no matching variable, or a variable list is empty.
   - Fail if cartesian size > `maxVariablesCartesianProductsPerTask` (error text tells you how to raise the limit).
   - Serialize the template body to YAML text, substitute each `${name}` once (no recursion), deserialize each combination.
   - Set `_varVariantIndex` (0-based) on each expanded def; log expand count.
4. Downstream migrator is unchanged — one `MigrateTableTask` per expanded def.

Substitution is raw string insert into YAML text, so it works for `whereClause`, `dataFilterDefinitions.filterOptions.mvelRule`, or any other text in that entry. Operator owns CQL/MVEL validity.

## Naming and start confirm

- `DbMigrator` assigns display names: `#<index> - <label>` plus ` varVariant_<N>` when `_varVariantIndex` is set.
- After tasks init: log the task list, then require confirm:
  - Interactive: type `Y` / `N`.
  - Non-interactive (`nohup`) without `-y`: fail fast (pass `-y` / `--yes`).
  - `-y` / `--yes`: assume yes and start.

Operator how-tos: [docs-user/how-to-start-migration-v1.0.md](../docs-user/how-to-start-migration-v1.0.md), [docs-user/config-guide-v1.0.md](../docs-user/config-guide-v1.0.md).

## Config knobs

- **`variables`** (per table entry): map of name → list of string pieces.
- **`maxVariablesCartesianProductsPerTask`** (top-level, default 16): max combinations per templated entry.
