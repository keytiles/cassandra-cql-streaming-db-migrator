## TLDR

1. Prepare a YAML config (see [config-guide-v1.0.md](config-guide-v1.0.md)).
2. Run the jar with `-configYaml <path>`.
3. Review the printed task list; type `Y` to start (or pass `-y` when you cannot answer interactively).

## Prerequisites

- Java 8+ JRE
- Network access to source and target Cassandra/ScyllaDB contact points
- Target tables already exist (this tool migrates row data, not DDL)
- The fat jar (e.g. `cassandra-cql-streaming-db-migrator-1.2.0.jar`)

## Basic interactive start

```bash
java -Xmx256M -jar cassandra-cql-streaming-db-migrator-1.2.0.jar \
  -configYaml migrate.yaml
```

What happens:

1. Config is loaded (including any `variables` template expansion).
2. Source/target connections open; each table task is prepared.
3. You see a short list of task names, for example:
   - `#1 - event_counters_hourly_v3`
   - `#2 - tile_event_counters_hourly_v3 varVariant_0`
4. You are asked to confirm. Type `Y` (or `yes`) to schedule the work, or `N` to abort before any writes.

Use `-Xmx` (and other JVM options) on memory-sensitive hosts.

## The `-y` / `--yes` flag

After the task list is ready, the tool normally waits for confirmation. That is intentional — especially when a template expands into many tasks.

**`-y` (long form `--yes`)** means: assume yes, do not prompt, start immediately after printing the task list.

Use it when:

- You already reviewed the config and trust the expanded task list
- You run under **`nohup`**, cron, CI, or any session **without a TTY** (no interactive console)

Without `-y`, a non-interactive session **fails fast** with a message telling you to re-run with `-y`. That avoids hanging forever under `nohup`.

### Interactive with explicit yes

```bash
java -jar cassandra-cql-streaming-db-migrator-1.2.0.jar \
  -configYaml migrate.yaml \
  -y
```

Same as answering `Y` at the prompt.

### Long-running migration with nohup (recommended for large jobs)

`nohup` is optional but recommended when a migration may run for hours: the process keeps going if your SSH session drops, and logs go to a file.

```bash
nohup java -Xmx512M -jar ~/db-migration/cassandra-cql-streaming-db-migrator-1.2.0.jar \
  -configYaml migrate-normalcounters.yaml \
  -y \
  > migrate-normalcounters.log 2>&1 &
```

Notes:

- **`-y` is required** here (no TTY under typical `nohup … &`).
- Redirect stdout/stderr to a log file and use `tail -f migrate-normalcounters.log` to watch progress.
- Status lines appear every `printStatusEveryXSeconds` from your config.

Foreground alternative (still attached to your terminal — fine for dry-runs / small jobs):

```bash
java -jar cassandra-cql-streaming-db-migrator-1.2.0.jar \
  -configYaml migrate-simulate.yaml
```

Then answer `Y` when asked.

## Help

```bash
java -jar cassandra-cql-streaming-db-migrator-1.2.0.jar -h
```

Shows CLI options (`-configYaml`, `-y` / `--yes`, …).

## Tips

- Prefer running close to the **target** cluster (`targetDB.contactNodes: localhost:9042` on a target node) for write latency.
- Start with `simulateOnly: true` on table entries until the task list and throughput look right.
